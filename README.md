For the directory and suffix funcitonality, there were a couple tests. Initial tests included running "./words tests/example" to ensure the program could handle individual files and implicit setting the searched suffix as .txt. Tests included running "./words -s .md tests" and "./words tests" to make sure that the program ignores certain files and checks nested directories. Another test is running "./words -s .wadwad tests" and "./words -s.wadwad tests" such that it would correctly identify uncommon length suffixes. Address Sanatizer and the VS Code Debugger were also used identify and fix memory leaks and unidentified behavior.

For testing the word counting and parsing, I made several text files to check different cases rather than just using normal sentences. sample.txt checks basic word counting, capitalization, numbers separating words, and hyphens. counts.txt focuses on making sure repeated words are counted correctly. edge.txt checks different uses of hyphens, such as foo-bar, foo--bar, and hyphens at the start or end of words. apostrophe.txt checks words containing apostrophes and makes sure apostrophes by themselves aren't counted as words. I also made boundary.txt to check that words can continue past the 4096 byte read buffer without getting split incorrectly, particularly when a hyphen is at the end of one read. I chose these cases because they test specific rules from the assignment and situations where the parsing could go wrong, rather than just testing more files containing ordinary words.
